## 3. 关键设计决定（改动前请先读）

### 3.1 种子随机数

所有随机都通过注入的 `Rng` 参数走。**不允许任何全局随机源**，`tests/guards.test.ts` 会扫描 `src/` 与 `tests/` 下的全部 TypeScript 源码，连注释里的字面量都不放过。

代价是多写一个参数。收益是四件事同时成立：可回放、可复现、种子可分享、平衡测量无随机噪声。这不是洁癖——只要有一处绕过，这四件事就全都不可靠，而且破坏是静默的。

子流用 `rng.derive(label)` 派发（`'map'`、`'deck'`、`'combat'`…），这样改动某一条流的消耗次数不会连锁改变其他部分的结果。否则加一张牌就会让所有历史种子失效。

`newSeed()` 是唯一允许非确定性的地方，它用时间戳 + 计数器，刻意不借用全局随机函数。

### 3.2 事件流契约

`src/engine/types.ts` 里的 `BattleEvent` 是引擎与界面的唯一接口：引擎算出「发生了什么」并产出事件数组，界面只负责按顺序播出来。规则改动不需要动界面，界面改版不需要动规则。

`engine/types.ts` 自身不得 import 任何东西（守卫测试会拦），它是依赖图的根。

### 3.3 内容查询不抛错

`findCard()` 之类的查询对未知 id 返回 `undefined`，界面用 `cardOr()` 拿占位卡面。存档或回放里出现已删除的 id 时不会白屏。

这个选择是有代价的：调用方要处理 `undefined`。但反过来的做法（查询抛错）会让存档加载、回放、开发期手改状态每一处都需要防御代码，总量远超省下的这几行。

### 3.4 界面出错保留数据

`main.ts` 捕获渲染异常后显示可读的错误界面并保留玩家数据，不退回菜单、不清进度。白屏且控制台无线索是排查成本最高的失败；用一个更大的问题（数据丢失）去掩盖一个更小的问题（一次渲染失败）不划算。

### 3.5 界面分层与画布

- 静态界面（地图/商店/奖励）可以整块重建 DOM，简单可靠
- **时序轴战斗界面应当持久化 DOM、只改变化的部分**，用 Web Animations API 串事件回放（`await animation.finished` 天然适合按序播事件）。卡牌游戏有大量转场动画，全量重建会打断动画。M1 实现战斗界面时请遵守这条

## 4. 测试分层

| 文件 | 覆盖 |
|---|---|
| `tests/rng.test.ts` | 同种子可复现、分布均匀、派生子流独立、种子码往返、算法快照 |
| `tests/content.test.ts` | 内容校验、核心设计不变式（挂刻性价比、延迟量级）、查询不抛错、时序换算 |
| `tests/replay.test.ts` | 稳定序列化（键序无关、非有限数不塌缩）、状态哈希、种子→哈希链路 |
| `tests/guards.test.ts` | 跨文件一致性：零全局随机源、分层方向、舞台尺寸、字号下限、形态色带双轨、代码卫生 |
| `tests/ui-smoke.test.ts` | jsdom 真实点击走通标题→筹备→关于→返回，含剪贴板降级与空种子提示 |

纪律：断言失败信息要说清「哪里不对、该去看哪份文档」；修掉一个历史缺陷就在测试里留一条注释注明它。

## 5. 本地运行与调试

```bash
npm run dev                                  # http://localhost:5173
npx vite --port 5174 --strictPort            # 自查截图用，避开常用端口
npm run typecheck && npm test && npm run build
cd android && ./gradlew assembleDebug
```

`?debug` 会把内部状态挂到 `window.__chrono` 上，方便在控制台里检查当前种子与屏幕。

## 6. 版本号约定

版本号有**三处**，必须同步：`package.json` 的 `version`（经 `define` 注入界面）、`android/app/build.gradle` 的 `versionName` 与 `versionCode`、以及 git tag。

`versionCode` 漏加会导致侧载更新不被识别——这是个已经踩过的坑，不要重犯。

发布流程：

```bash
git tag v0.1.0
git push origin v0.1.0
gh run watch
gh release view
```
